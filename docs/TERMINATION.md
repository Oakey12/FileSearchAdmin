# Завершение процессов 1С: алгоритм и архитектура

## Слои

```
UI (cat-processes.ts)
  «Завершить у всех» · «Тест закрытия 1С» · «Завершить у выбранных» · «Тест у выбранных»
        │
App (app_ops.go): FinishAll · TestFinish · FinishEmployees · TestFinishEmployees
        │
ops (button.go): runTerminateOperation(work, dryRun)   ← один конвейер на 4 операции
        │  параллельно по серверам (MaxParallelServers), тайм-аут на сервер
remotefunc (remote.go): RunRemoteTerminate(ip, pids, dryRun)
        │  локальный powershell.exe, пароль через stdin
PsScript (psScript.go): -Action terminate [-ProcessIds …] [-DryRun]
        │  CIM/DCOM-сессия к серверу
Сервер: Win32_Process, taskkill.exe
```

Бой и тест различаются только флагом `dryRun`, который доходит до сценария на
сервере. Весь путь до необратимого шага у них общий, поэтому тест проверяет
ровно то, что будет выполнено при завершении.

## Алгоритм на сервере (`Invoke-TerminateAction`)

1. **Поиск.** `Win32_Process` по имени (и по выбранным PID). Процесс опознаётся
   по паре *PID + время запуска*: PID может достаться другому процессу.
   Дополнительно ищутся другие варианты 1С (`1cv%`: `1cv7.exe`, `1cv7l.exe`,
   `1cv8.exe`…), которые не входят в список завершения.
2. **Владельцы** сеансов: `quser` (≤ 3 с), при неудаче — `GetOwner`.
3. **Тест** (`-DryRun`) на этом месте запускает на сервере `taskkill` с фильтром
   по несуществующему имени: он стартует, перебирает процессы и ничего не
   завершает. Это проверяет запуск команды на сервере и показывает, сколько
   taskkill работает на этом сервере. Дальше — список того, что было бы
   завершено, и выход.
4. **Шаг 1 — `taskkill /F` пакетом** (по 200 PID, фильтр `IMAGENAME` как защита
   от чужого PID). Ждём завершения *самого taskkill* (до 20 с), затем 2 с на
   выход процессов.
5. **Шаг 2 — `Win32_Process.Terminate`** для оставшихся, по одному: синхронный
   вызов с кодом ответа (2 — доступ запрещён, 3 — нет привилегий…).
6. **Шаг 3 — ожидание выхода** до 8 с: `TerminateProcess` асинхронен.

## Статусы в журнале

| Строка сценария | Смысл |
|---|---|
| `KILLED` | процесс завершён; указан способ (taskkill / Terminate) |
| `KILL_FAIL` | не завершён, с причиной (код Terminate или ошибка) |
| `KILL_PENDING` | запрос принят, но процесс не вышел за 8 с — зависший ввод-вывод (база на сетевой папке, драйвер ключа защиты) |
| `GONE` | выбранный PID уже не выполняется |
| `VARIANT` | запущена 1С под другим именем — не входит в список завершения |
| `PLAN` / `PROBE` | только тест: что было бы завершено / проверка запуска taskkill |
| `STEP_WARN` | шаг не сработал, продолжаем резервным |

## Почему прежний вариант мог «не завершать» на одном сервере

- `Win32_Process.Create` возвращает «taskkill запущен», а не «отработал»; проверка
  длилась 1 с. Даже на простаивающей машине taskkill работает 0,75–1 с — на
  нагруженном терминальном сервере результат объявлялся провалом раньше, чем
  taskkill успевал отработать, а причина отказа не была известна.
- Тайм-ауты `Create` и запроса каталога Windows — 5 с: медленный сервер находил
  процессы, но не успевал запустить taskkill.
- Не было резервного способа: если taskkill на сервере не срабатывал, процесс
  оставался.
- Проверка «PID ещё есть» без времени запуска: переиспользованный PID считался
  провалом.
- Поиск только `1cv7s.exe`: 1С под другим именем выглядела как «процессов нет».

## Что смотреть при проверке на проблемном сервере

Запустите «Тест закрытия 1С» на этом сервере:
- `проверка запуска taskkill — НЕ запускается` или `… не завершился за 20 с` —
  проблема в запуске команд на сервере; при завершении сработает резервный
  `Terminate`;
- `внимание — запущены другие процессы 1С` — 1С на сервере работает под другим
  именем;
- список «у кого закрылась бы» пуст при открытой 1С — проверьте имя процесса и
  учётную запись.

После боевого завершения смотрите на `НЕ завершён … : <причина>` и
`ожидают выхода`.
