# FileSearchAdmin — дизайн

**Дата:** 2026-10-22
**Репозиторий:** `C:\Users\1108\FS\FileSearchAdmin` (origin `github.com/Oakey12/FileSearchAdmin`)
**Статус:** черновик на согласование. Код не пишется до «ок».

## 1. Замысел и зачем

Перенести **весь** админский функционал приложения `C:\Users\1108\FS\1Cproc`
(сейчас Go + Fyne) в новую утилиту в `FileSearchAdmin`, пересобрав её на том же
фреймворке и в том же визуальном стиле, что и `C:\Users\1108\FS\FileSearch`
(Wails v2.16 + ванильный TypeScript/Vite). Цель — единый «семейный» вид двух
утилит, современный UI с удобной раскладкой элементов управления и вывода, и
быстрый, оптимизированный бэкенд на Go. После того как утилита станет
полноценно рабочей, отдельно настраивается Nginx для раздачи списка серверов и
обновлений.

**Почему именно так.** Логика удалённого управления в 1Cproc не завязана на
Fyne: весь «удалённый» механизм — это запуск **локального** `powershell.exe`,
которому через stdin передаются логин/пароль/скрипт, а PowerShell открывает
CIM/DCOM-сессию к машине по IP и выполняет действия через `Win32_Process.Create`
и WMI-запросы. Значит, Go-пакеты с этой логикой (`remoteFunc`, `psScript`,
`config`, `constAndStruct`, `officeEditor`) переносятся почти без изменений, а
переписывается только слой UI: Fyne-виджеты → привязанные методы `App` +
ванильный TS-фронтенд в стиле FileSearch.

## 2. Что переносим (полный инвентарь функций 1Cproc)

Три вкладки, боковой журнал, самообновление:

**Вкладка «Завершение 1С» (главная):**
- Список серверов с множественным выбором + ручной ввод IP.
- Поля логина (`DOMAIN\user` или `.\user`) и пароля (в памяти, не на диск).
- «Найти открытые 1cv7s» на выбранных серверах.
- «Сканировать сотрудников» с открытой 1С → список с галочками.
- «Завершить 1С у выбранных сотрудников».
- «Завершить 1cv7s у всех на выбранных серверах».
- **Оповещение пользователей**: поле текста + выпадающий список шаблонов +
  кнопка «Оповестить». На цели запускается `msg.exe * /TIME:86400 "текст"`.

**Вкладка «Команды»:** удалённое выполнение PowerShell-сценария.
- Ввод IP/логина/пароля, режим «На компьютере» или «В сессии пользователя».
- В режиме сессии — скан пользователей, выбор активной сессии (Session ID).
- Ввод сценария или прикрепление `.ps1` через системный диалог, выполнение с
  подтверждением. Передача сценария — через зашифрованное временное задание в
  реестре цели (не файлом), с очисткой. Вывод — в журнал, лимит 524288 символов.

**Вкладка «Сканер и удаление»:**
- Скан установленных программ по IP → список → удаление выбранной программы.
- Скан файлов в папке (по пути или по сессии пользователя) → список.
- Открытие и редактирование файла: текст, `.docx` (абзацы), `.xlsx` (ячейки),
  с резервной копией оригинала.
- Удаление выбранного файла (с подтверждением).
- «О системе»: сбор сведений о машине (WMI: `Win32_ComputerSystem`,
  `Win32_OperatingSystem`, `Win32_Processor`, `Win32_BIOS`, сеть, диски,
  аптайм) и копирование.
- Скан пользователей на сервере → выбор пользователя/сессии.

**Сквозное:**
- Боковой журнал (drawer) с копированием и кнопкой открытия папки логов.
  Логи в `%LocalAppData%\...\Logs`, ротация 5×10 МиБ.
- Самообновление по манифесту + самозамена (`--pid/--current/--new`).
- Загрузка списка серверов с сервера обновлений, кэш в `%LOCALAPPDATA%`,
  фолбэк на кэш при недоступности, ручной ввод IP. Переопределение
  переменными среды.

## 3. Цели / не-цели / анти-цели

**Цели**
- Полный перенос функций из раздела 2.
- Внешний вид и ощущения как у FileSearch: тёмная/светлая темы, фоны
  «Лес»/«Частицы», стеклянные карточки, та же типографика и токены цветов.
- Бэкенд Go, архитектура и соглашения как в FileSearch (один `App`, привязка
  `Bind: []any{app}`, стриминг прогресса через `runtime.EventsEmit`).
- Сборка без Node: `frontend/dist` и `frontend/wailsjs` коммитятся, собирается
  `wails build -s -skipbindings` (на машине Node нет).
- Удобная раскладка управления и вывода; быстро и оптимизированно.

**Не-цели**
- Переписывание логики удалённого транспорта — переносим как есть.
- Агент на целевых машинах — его нет и в 1Cproc, всё через DCOM/WMI.
- Настройка Nginx в рамках этого этапа (отдельный шаг после готовности).
- Кроссплатформенность: утилита Windows-only (как и 1Cproc).

**Анти-цели (провал, даже если «работает»)**
- Изменение модели безопасности: пароль не должен попадать на диск, в журнал
  или в URL; манифест `asInvoker` (без автоподъёма прав).
- Необратимые действия (удаление программы/файла, произвольный скрипт) без
  отдельного подтверждения.
- Зависимость сборки от Node/npm на машине пользователя.
- «Тяжёлые» WMI-классы (напр. `Win32_Product`), замедляющие скан.

## 4. Ограничения

- Windows + Windows PowerShell 5.1; доступ DCOM/CIM к целям; учётка
  администратора целевых машин.
- Go 1.25+, Wails v2.16, WebView2 (есть на машине). Node ставится на эту машину
  (решение по фронтенду) для сборки фронта и генерации привязок.
- Git push требует интерактивного входа GCM — делает пользователь.
- `wails.io` отдаёт 403 на fetch; документация берётся с raw.githubusercontent.

## 5. Как ложится на Wails (решения, которые я принял)

**Структура Go (зеркало FileSearch):**
```
FileSearchAdmin/
  main.go              // wails.Run, тема окна, embed frontend/dist
  app.go               // тип App + привязанные методы (бывшие кнопки Fyne)
  go.mod               // module filesearch-admin
  internal/
    remote/            // ← 1Cproc internal/remoteFunc (транспорт PS/CIM/DCOM)
    psscript/          // ← 1Cproc internal/psScript (PS-сценарии)
    config/            // ← 1Cproc internal/config (список серверов, кэш)
    model/             // ← 1Cproc internal/constAndStruct (структуры)
    office/            // ← 1Cproc internal/officeEditor (docx/xlsx)
    ops/               // оркестрация операций: бывший internal/buttonFunc без
                       //   Fyne — поиск/скан/команды/файлы/программы/система.
                       //   Единое состояние операции (beginOperation, отмена,
                       //   MaxParallelServers) переезжает на App + события.
    journal/           // лог-ядро из internal/auxiliaryFunc БЕЗ Fyne-виджета;
                       //   сам журнал-drawer — на фронтенде
    update/            // самообновление: порт 1Cproc internal/updater +
                       //   cmd/updater (helper-замена через --pid/--current/--new)
  frontend/            // ванильный TS/Vite как в FileSearch
    src/               // style.css, theme.ts, backdrop.ts, drawer.ts, toast.ts
                       //   переиспользуются; tabs/команды/скан — новые модули
    dist/              // коммитится
    wailsjs/           // коммитится
  build/               // иконка, манифест (asInvoker)
  tools/release.ps1    // порт релизного скрипта FileSearch
```

**Слой UI → методы App.** Каждый обработчик кнопки Fyne становится методом
`App`, который принимает параметры из фронтенда (цели, креды, текст) и либо
возвращает результат, либо стримит строки журнала/прогресс через события.
Черновой список методов: `ServerList`, `Notify`, `SearchProcesses`,
`ScanEmployees`, `CompleteEmployees`, `FinishAll`, `RunCommand`, `ScanUsers`,
`ScanPrograms`, `UninstallProgram`, `ScanFiles`, `ReadRemoteFile`,
`SaveRemoteFile`, `DeleteRemoteFile`, `ScanSystemInfo`, `PickScriptFile`,
`CheckUpdate`, `InstallUpdate`, `SaveWindowTheme`, `Version`.

**События (как `search:batch`/`update:progress` в FileSearch):**
`journal:line` (строки журнала по мере выполнения), `operation:status`
(идёт/завершено/отменено), `scan:progress`. Одна операция за раз (как в
1Cproc: `beginOperation`), кнопка ручной отмены, `MaxParallelServers = 2`.

**Фронтенд.** Переиспользуем из FileSearch без изменений: `style.css` (токены
цветов/типографики), `theme.ts` (тёмная/светлая), `backdrop.ts`
(«Лес»/«Частицы», стеклянные карточки), `drawer.ts`, `toast.ts`, `format.ts`.
Новые модули: `tabs.ts` (три вкладки), `main-tab.ts`, `commands.ts`,
`scanner.ts`, `journal.ts`, формы кредов/серверов. Раскладка — карточки на
стеклянном фоне: сверху выбор серверов + креды, ниже блоки действий, справа/снизу
выезжающий журнал.

**Диалоги.** Системные файловые диалоги Fyne (`nativeDialog`) заменяются на
Wails `runtime.OpenFileDialog`/`SaveFileDialog`.

**Сборка фронтенда.** Решение: пользователь ставит **Node.js на эту машину**,
дальше фронтенд собирается штатно (`npm install`, `tsc && vite build`), а
`wailsjs`-привязки генерирует `wails generate module`. Код FileSearch
(`style.css`, `theme.ts`, `backdrop.ts`, `drawer.ts`, `toast.ts`, `format.ts`)
переиспользуется один-в-один. `frontend/dist` и `frontend/wailsjs` коммитятся,
так что релизная сборка остаётся `wails build -s -skipbindings` и не требует
Node на машинах, где только собирают бинарь.

**Безопасность.** Креды только в памяти, в PowerShell через stdin; необратимые
действия с подтверждением; манифест `asInvoker`. Новая поверхность в Wails:
пароль вводится в HTML-поле (куча JS рендерера WebView2) и передаётся как
аргумент привязанного метода по IPC-мосту. Это допустимо — пароль остаётся в
памяти процесса, не пишется на диск, в журнал и в URL, что и означает анти-цель.
Решение: обычный поток «поле → метод App → память Go», без хранения; поле
очищается при закрытии окна, в журнал пароль не попадает.

**Оркестрация (бывший buttonFunc, ~4400 строк).** Fyne-свободные части
(scanner/remote_files/remote_office/remote_users/systemInfo/uninstall/
findApplication, ~2100 строк) переносятся в `internal/ops` почти как есть.
Fyne-связанные части (`button.go`, `command.go`, ~1200 строк: сигнатуры на
`*widget.Entry`/`*widget.CheckGroup`, `dialog.ShowConfirm`, `fyne.Do`,
глобальное состояние операции) **переписываются** на методы App + события
`journal:line`/`operation:status`. Логгер/журнал из `auxiliaryFunc`
разделяется: лог-ядро (ротация, запись) — в `internal/journal`, визуальный
drawer — на фронтенде. Это не «только UI»: ~1200 строк оркестрации — настоящий
рерайт, заложен в план.

**Обновление.** Берём схему 1Cproc: отдельный helper-режим EXE
(`--pid/--current/--new`), который ждёт выхода родителя, подменяет файл и
перезапускает — он надёжно меняет занятый работающий EXE. Формат манифеста
(`{version,url,sha256,notes}`) единый с 1Cproc/FileSearch, чтобы один Nginx
раздавал обновления всем трём утилитам. `tools/release.ps1` портируется из
1Cproc.

**Проверка готовности.** Удалённые операции требуют доступной по DCOM/CIM цели
и админ-кредов — на этой dev-машине их нет. Поэтому «готово» = (1) перенесённые
юнит-тесты 1Cproc проходят, (2) в `ops`/транспорте есть шов для подмены
транспорта мок-реализацией, (3) smoke-запуск окна с мок-транспортом (UI,
вкладки, журнал, темы/фоны). Реальный end-to-end по сети прогоняет пользователь
на своём контуре. Если есть тестовая цель — подключим её на этом шаге.

## 6. Nginx (следующий этап, не в этой поставке)

После готовности утилиты Nginx раздаёт для неё `servers.json` и манифест
обновлений + бинарники (по аналогии с 1Cproc:
`http://<host>/updates/1cproc/servers.json` и `.../latest.json`). Новый
путь — напр. `/updates/filesearchadmin/`. Точный хост/путь и наличие TLS
уточняются на этом этапе; в коде адрес выносится в константу и переопределяется
переменной среды, как в 1Cproc.

## 7. Что остаётся на исполнителя

- Точные сигнатуры методов `App` и формы событий (черновик в §5).
- Конкретная вёрстка карточек и расположение контролов (в духе FileSearch).
- Порядок переноса пакетов и адаптация импорт-путей под `filesearch-admin`.
- Название/версия продукта в `wails.json` и заголовке окна (предложу при
  согласовании; по умолчанию «Удалённое управление 1С — Администрирование»).
- Перенос и адаптация тестов 1Cproc (там широкое покрытие) под новые пакеты.

## 8. План реализации (после согласования)

Детальный пошаговый план пишется отдельно (superpowers:writing-plans) и кладётся
рядом. Ориентировочные этапы: (1) каркас Wails + фронтенд-инфраструктура из
FileSearch; (2) порт Go-пакетов транспорта/скриптов/конфига; (3) методы App +
события; (4) вкладка «Завершение 1С» с оповещением; (5) вкладка «Команды»;
(6) вкладка «Сканер и удаление» с редакторами; (7) журнал, обновление, сборка
без Node; (8) прогон тестов и проверка в реальном окне.
